# ZEISS_Assessment
ZEISS  Assessment Lisbon - Backend test

## Run locally

Requires the .NET 10 SDK selected by `global.json`.

```sh
dotnet restore
dotnet run --project src/ZEISS.ProductManagement.Api --launch-profile http
```

- API: http://localhost:5257/api/products
- Swagger UI (Development only): http://localhost:5257/swagger
- OpenAPI (Development only): http://localhost:5257/openapi/v1.json

OpenAPI is generated by ASP.NET Core. Swagger UI is provided by the NSwag.AspNetCore
package, with assets served locally; no custom HTML page or CDN is required.

## Current implementation status

All nine product routes are declared but not implemented. Requests with valid
HTTP binding and valid request DTOs return `501 Not Implemented` with ProblemDetails.
No product data is read, created, updated or deleted. Routes are grouped in
`ProductsController`; `[ApiController]` automatically rejects invalid creation/update
DTOs with `400 Bad Request` and ValidationProblemDetails. Malformed JSON or
incorrectly typed parameters can also be rejected before reaching an action.

OpenAPI lists the intended success response schemas as the future contract, not
as currently available behavior. Stock-operation and search/filter validation,
business operations and the remaining HTTP error contracts will be connected
when the use cases are implemented.

Creation accepts initial stock. Updates contain only name, description and price;
subsequent stock changes belong to the dedicated stock endpoints.

## Build and tests

```sh
dotnet build --configuration Release
dotnet test tests/ZEISS.ProductManagement.UnitTests --configuration Release
dotnet test tests/ZEISS.ProductManagement.IntegrationTests --configuration Release
```

The current integration tests exercise HTTP routing, DTO validation and API
documentation using WebApplicationFactory. They do not yet test SQL Server or
persistence.
